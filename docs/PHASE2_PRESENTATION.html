            Limitations That Motivated Phase 2
            4 Gaps Identified
          

          
    
            
  • Single DNS Point of Failure: Only one dnsmasq server existed; if it stopped, app.protocolx.test failed to resolve.
    • 
            
  • No Service Isolation: Any LAN client could bypass Nginx and hit Backend A (:3001) or B (:3002) directly.
    • 
            
  • Untuned Failover & Single Edge: Nginx used default upstream timeouts, and there was no standby Edge if Mac 2 went offline.
    • 
            
  • Hardcoded Paths & No Live Observability: Phase 1 IPs/paths were static and there was no central health dashboard.

Requirement D · Fault Tolerance

        
High Availability & Passive Backend Failover

      


      

        

          
Passive Failover MechanismTested successfully

          

            
WhatKeeping the app available when one backend server crashes.

            
WhyOne Node.js outage must not break user requests.

            
HowNginx max_fails=2 fail_timeout=10s + proxy_next_upstream.

          

          
    
            
  • Step 1: Both backends healthy → 6 requests alternate B → A → B → A → B → A.
    • 
            
  • Step 2: Stop Backend A on Mac 3 (:3001) → 4/4 requests succeed via Backend B.
    • 
            
  • Step 3: Restart Backend A and wait fail_timeout=10s → alternation B → A → B → A resumes.
    • 
            
  • Honest Limitation: Mac 2 Nginx Edge remains a single point of failure unless DNS cutover runs.
    •

DNS-Based Edge CutoverTested successfully

          

            
WhatMoving the HTTPS entry point from Mac 2 to Mac 4 via DNS.

            
WhySupports Edge maintenance or Mac 2 failure without new hardware.

Real Engineering Challenges

        
Problems We Faced & How We Solved Them

      


      

        

          
            
Problem FacedRoot Cause / InvestigationSolution / Workaround

          
          
            

              1. Macs sleeping on battery
              macOS powered down Wi-Fi after ~30s of inactivity, dropping Edge and backends.
              Ran caffeinate -d -i -m -u & on Mac 2, Mac 3, and Mac 4.
            

            

              2. DHCP IP drift across campus LAN
              Phase 1 IPs changed; /etc/resolver/test and nginx.conf were stale.
              Recorded live en0 IPs and updated DNS/Nginx configs dynamically.
            

            

              3. TLS key/cert mismatch on Mac 2
              Mac 2's local .key did not match the repo .crt (error:05800074).
              Regenerated .crt from Mac 2's key and trusted it in Mac 1 Keychain.
            

            

              4. Script binary path bug
              which ... && echo ... duplicated the binary path across two lines.
              Replaced with clean command -v / if-elif checks in starter scripts.
            

            

              5. TTL script not reloading config
              killall -HUP dnsmasq does not reload dnsmasq.conf; dig skips OS cache.
              Restarted dnsmasq and queried both dig and dscacheutil -q host.
            

            

              6. PF rule & rollback section order
              block in quick preceded pass; saving -sn before -sr broke pfctl -f.
              Fixed rule order and enforced scrub → nat/rdr → filter in rollback.
            

            

              7. Dashboard auth & agent errors
              Plaintext passcode lacked CSRF/replay; background fetch hit EHOSTUNREACH.
              Added scrypt hashes, HttpOnly sessions, CSRF/nonces, and Socket.IO reporting.

What We Learned4 Macs Healthy

            
    
              
  • Redundancy removes SPOFs: Backup DNS and multi-backend failover keep users online during node crashes.
    • 
              
  • Defense in depth: TLS 1.3 at Edge + pfctl isolation + CSRF/nonce-protected control plane.
    • 
              
  • Layer-by-layer debugging: Checking DNS → TCP → TLS → App pinpoints failures fast.
    • 
              
  • Remaining limitation: Mac 2 Edge still requires DNS cutover if it goes offline.
