Baseline Architecture

Phase 1: What We Built & Its Limitations

Phase 1 proved end-to-end private web delivery across four Macs using private DNS, TLS 1.3 reverse proxying, and two Node.js backends.

Phase 1 Request Flow (Verified in Repo) Baseline Working
  • Private domain app.protocolx.test resolved locally via dnsmasq.
  • Nginx terminated TLS 1.3, added Cache-Control: max-age=10, and balanced A/B.
Limitations That Motivated Phase 2 4 Gaps Identified
  • Single DNS Point of Failure: Only one dnsmasq server existed; if it stopped, app.protocolx.test failed to resolve.
  • No Service Isolation: Any client on the LAN could bypass Nginx and hit Backend A (:3001) or B (:3002) directly.
  • Untuned Failover & Single Edge: Nginx used default upstream timeouts, and there was no standby Edge if Mac 2 went offline.
  • Hardcoded Paths & No Live Observability: Phase 1 IPs/paths were hardcoded and there was no central health dashboard.

Phase 2 Extensions

Six Mandatory Phase 2 Enhancements

Phase 2 transforms ProtocolX from basic connectivity into a fault-tolerant, firewall-isolated, observable distributed system.

1. Backup DNSTested
  • Secondary dnsmasq on Mac 4 mirrors Mac 1 records.
  • Eliminates single DNS failure.
2. DNS TTL & CutoverTested
  • 30-second TTL on migration.protocolx.test.
  • Demonstrates caching vs flush.
3. Service Isolation (PF)Tested
  • macOS pfctl allows only Mac 2 Edge to :3001/:3002.
  • Includes backup-and-restore rollback.
4. Backend HA & FailoverTested
  • Passive failover: max_fails=2 fail_timeout=10s.
  • Automatic recovery after outage.
5. Controlled Edge MigrationTested
  • Standby Nginx on Mac 4 (:8443) + DNS cutover.
  • Clean restoration to Mac 2 Edge.
6. Layer TroubleshootingTested
  • Ordered checks: DNS → TCP → TLS → App.
  • Plus live 4-Mac Central Dashboard.

Requirement D · Fault Tolerance

High Availability & Passive Backend Failover

Passive Failover MechanismTested successfully
WhatKeeping the app available when one backend server crashes.
WhyOne Node.js outage must not break user requests.
HowNginx max_fails=2 fail_timeout=10s + proxy_next_upstream.
  • Step 1: Both backends healthy → 6 requests alternate B → A → B → A → B → A.
  • Step 2: Stop Backend A on Mac 3 (:3001) → 4/4 requests succeed via Backend B.
  • Step 3: Restart Backend A and wait fail_timeout=10s → alternation B → A → B → A resumes.
  • Honest Limitation: Mac 2 Nginx Edge remains a single point of failure unless DNS cutover runs.
Live Failover & Recovery TraceNginx 1.31.10
# Phase 1: Normal Round-Robin Req 1..6 → X-Backend: B, A, B, A, B, A (all 200 OK) # Phase 2: Backend A Stopped (Mac 3 :3001 down) Failover 1..4 → HTTP/1.1 200 OK · X-Backend: B (Note: passive failover on failed connect, not active probe) # Phase 3: Backend A Restarted + 11s (> fail_timeout=10s) Recovery 1..4 → X-Backend: B, A, B, A (all 200 OK)
Key Distinction for Viva
Open-source Nginx uses passive failover (detects failure on real client requests), not active background health checks.

Real Engineering Challenges

Problems We Faced & How We Solved Them

Problem FacedRoot Cause / InvestigationSolution / Workaround
1. Macs sleeping on battery macOS powered down Wi-Fi after ~30s of inactivity, dropping Edge and backends. Ran caffeinate -d -i -m -u & on Mac 2, Mac 3, and Mac 4.
2. DHCP IP drift across campus LAN Phase 1 IPs changed; /etc/resolver/test and nginx.conf were stale. Recorded live en0 IPs and updated DNS/Nginx configs dynamically.
3. TLS key/cert mismatch on Mac 2 Mac 2's local .key did not match the repo .crt (error:05800074). Regenerated .crt from Mac 2's key and trusted it in Mac 1 Keychain.
4. Script binary path bug which ... && echo ... duplicated the binary path across two lines. Replaced with clean command -v / if-elif checks in starter scripts.
5. TTL script not reloading config killall -HUP dnsmasq does not reload dnsmasq.conf; dig skips OS cache. Restarted dnsmasq and queried both dig and dscacheutil -q host.
6. PF rule & rollback section order block in quick preceded pass; saving -sn before -sr broke pfctl -f. Fixed rule order and enforced scrub → nat/rdr → filter in rollback.
7. Dashboard auth & agent errors Plaintext passcode lacked CSRF/replay; background fetch hit EHOSTUNREACH. Added scrypt hashes, HttpOnly sessions, CSRF/nonces, and Socket.IO reporting.
